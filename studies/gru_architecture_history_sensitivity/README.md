# GRU architecture / history-length sensitivity study

A separate scientific study to justify the GRU architecture (hidden size,
layer count) and input-history duration used in the thesis. It is **not**
an unrestricted hyperparameter search: architecture is a 3x2 grid (Stage 1)
and history length is a small, physically-motivated grid keyed to each
dataset's natural period T_n = 1/f_n (Stage 2), both trained under the
feedback-compatible, no-acceleration, noise-free formulation

    x_t = [h* = h/D,  hdot* = hdot/U,  Ur]

Six architectures (H in {32,64,128} x L in {1,2}) times three seeds
(123, 456, 789) = 18 runs per dataset for Stage 1 -- always described that
way, never as "18 architectures."

This directory is fully self-contained. It imports the validated
production modules under `src/viv_analysis/` and never copies their
source. **One production file was changed**, with approval: an opt-in
`--skip_test_eval` flag was added to `src/viv_analysis/train_gru.py` (see
"Test evaluation" below) -- default `False`, i.e. unchanged behavior for
every existing caller. See `manifests/stage0_audit.json` (generated by
`scripts/audit_pipeline.py`) for the full audited production
hyperparameters this study holds fixed, the six-point trainable-parameter
table (computed directly from `VIV_GRU`, not waited on until a training
job produces it), and the discrepancy record.

## Directory layout

- `configs/` -- frozen grid definitions (architecture_grid.json,
  cylinder_history_grid.json, bridge_history_grid.json).
- `scripts/` -- see "Pipeline" below.
- `jobs/` -- generated LSF (bsub) job arrays. Nothing here is submitted by
  any script in this study; generation and submission are separate steps.
- `manifests/` -- `stage0_audit.json` (audit_pipeline.py output),
  `study_manifest.json` (frozen grid, read by generate_jobs.py instead of
  reconstructing configs implicitly), `selection_manifest_stage{1,2}.json`
  (written by `select_configuration.py --freeze`; this is also the key
  `unlock_test_evaluation.py` requires).
- `results/` -- every checkpoint/metric this study's real Stage 1/2 runs
  produce, mirroring production's own results/ layout but entirely inside
  this study (`results/<dataset>/stage{1,2}/<H>_<L>_<seq>_<seed>/`).
  Nothing is ever written to the repo's top-level `results/` by this study.
- `smoke/` -- temporary end-to-end validation runs only (see "Smoke
  tests"). Never read by `collect_results.py`, `select_configuration.py`,
  or any frozen manifest.
- `reports/` -- `collect_results.py` / `select_configuration.py` output
  (per-run tables, seed-aggregated tables, Pareto tables) plus
  `unlock_test_evaluation.py`'s final test-partition report.
- `tests/` -- see "Tests".

## Pipeline

1. `scripts/audit_pipeline.py` -- read-only. Confirms the actual
   production hyperparameters/partitions, computes the six-point
   trainable-parameter-count table, and writes `manifests/stage0_audit.json`.
   Run this first; everything else assumes it has run. Heavy (loads the
   real cylinder200 + bridge CFD cache) -- submit via batch, do not run on
   the login node.
2. `scripts/generate_jobs.py --freeze-manifest` -- combines
   `configs/*.json` + the Stage 0 audit into `manifests/study_manifest.json`.
3. `scripts/generate_jobs.py` -- reads the frozen manifest and writes bsub
   scripts into `jobs/`. Stage 2 scripts are written but refuse to run
   (their #BSUB directives are commented out AND the script body itself
   exits 1) unless `manifests/selection_manifest_stage1.json` exists and
   is frozen.
4. `scripts/train_sensitivity.py --dataset ... --hidden_size ... --num_layers
   ... --seq_len ... --seed ... --stage ...` -- trains one configuration
   from scratch by calling `viv_analysis.train_gru.main()` in-process,
   after temporarily overriding `config.config['hidden_size']`/
   `['num_layers']` (train_gru's CLI has no flag for those two; --seq_len
   IS a native flag and is passed straight through). Writes into this
   study's own `results/` via a relative `--exp_subdir` path (train_gru's
   own existing flag). **Always** passes `--skip_test_eval` -- no test
   prediction is ever computed for any Stage 1/2 run. Writes
   `study_receipt.json` only after asserting `run_config.json` and
   `metrics_gru.json` both confirm the test partition was untouched.
5. `scripts/evaluate_open_loop.py --run_dir ...` -- open-loop metrics
   (R2/RMSE/NRMSE/MAE, aggregate + per-case) computed **only** over the
   run's canonical validation cases -- hard-asserts the evaluated set's
   size AND identity match the Stage 0 audit's own frozen validation-case
   record for that dataset (4 for cylinder200, 5 for bridge); refuses to
   run otherwise. Uses the same production `teacher_forcing_rollout`
   function production training uses for its (historically test-only)
   rollout, via the shared `_common.compute_open_loop_metrics`.
6. `scripts/evaluate_closed_loop.py --run_dir ...` -- full-duration
   (500s cylinder200 / 700s bridge, matching current production
   convention) closed-loop evaluation, swept over **exactly the canonical
   validation cases** (same hard assertion as step 5) -- never train
   cases, never test cases. This is the sweep that feeds selection.
   Shells out to `coupled_inference.py`'s own CLI exactly the way
   `evaluate_all.py` does (via the shared `_common.run_coupled_sweep`),
   then reuses `evaluate_all._compute_gate` (cylinder) or
   `reference_quality.build_status_aware_report` (bridge, joined against
   `results/bridge_reference_status.csv`).
6b. `scripts/evaluate_closed_loop_train_diagnostic.py --run_dir ... [--ur 6.7385]` --
    a **separate, explicitly-labelled** command for training-case
    diagnostics (including the bridge Ur=6.7385 mechanistic control).
    Writes to `<run_dir>/closed_loop_train_diagnostic/`, a directory
    `collect_results.py` never reads. Never invoked by the Stage 1/2 job
    arrays `generate_jobs.py` produces; has zero effect on selection.
7. `scripts/collect_results.py --dataset ... --stage ...` -- aggregates
   every run's receipts into a per-run table and a median/IQR-across-seeds
   table in `reports/`, one row per **configuration** (grouped by
   dataset/stage/hidden_size/num_layers/seq_len/history_label), with the
   3 seeds listed explicitly rather than averaged away.
8. `scripts/select_configuration.py --dataset ... --stage ...` -- builds
   the Pareto/hierarchical ranking table (see "Selection rule" below), one
   row per configuration. Pass `--freeze` only after reviewing it, to
   write `manifests/selection_manifest_stage{stage}.json`, which names the
   selected **configuration** -- `{hidden_size, num_layers}` for Stage 1;
   `{hidden_size, num_layers, sequence_samples, physical_duration_s,
   history_label}` for Stage 2 -- together with all 3 of its seed-specific
   `selected_run_dirs`. Refuses to freeze unless exactly the 3 canonical
   seeds (123/456/789) are present; a single favorable seed can never
   stand in for a configuration.
9. `scripts/unlock_test_evaluation.py --selection-manifest ...` -- **the
   only place in this study a test prediction is ever computed.** Refuses
   to run unless the manifest exists, is `frozen: true`, and names exactly
   3 seed-specific run_dirs, each of which must itself report
   `skip_test_eval: true` in its own `run_config.json`. Computes test
   metrics for the first time, for each of the 3 seeds independently
   (reusing `_common.compute_open_loop_metrics` against
   `run_config['test_cases']` instead of `val_cases`), and reports each
   seed plus the median and IQR -- it never selects or highlights the
   best-performing seed as "the" result.

## Test evaluation: prevention, not concealment

Training cases are used for fitting. Validation cases are used for early
stopping, model selection, and every comparison in this study, including
the closed-loop sweep that feeds selection. **No test prediction exists
anywhere in this study until `unlock_test_evaluation.py` is run against an
already-frozen, configuration-level selection manifest.**

This required one production-code change, applied with approval:
production `train_gru.py` previously unconditionally evaluated the test
partition and wrote `test_metrics` plus per-case test-only entries in
`tf_results` into `metrics_gru.json` on every run, with no way to opt out.
An opt-in `--skip_test_eval` flag (default `False` -- every existing
caller's behavior is unchanged) now prevents the test dataframe/loader
from ever being constructed, test inference from ever running, and any
test metric/plot/artifact from ever being produced; only the test case
*labels* survive, in `run_config.json`'s `test_cases` field. Every
training job this study runs passes this flag unconditionally
(`train_sensitivity.py`). There is no `_test_locked/` directory, no
redaction step, and no post-hoc concealment anywhere in this study --
prevention at the source.

## Selection rule

Selection happens at the **configuration** level -- `(dataset,
hidden_size, num_layers)` for Stage 1, `(dataset, hidden_size, num_layers,
sequence_samples, physical_duration_s)` for Stage 2 -- aggregated across
all 3 seeds by median and IQR. A single run/checkpoint/seed is never
selected on its own.

Fixed hierarchy, not a tunable weighted scalar:

1. Reject invalid/NaN/failed runs.
2. Require open-loop validation retention (`delta R2_val >= -0.005` vs. the
   fresh H64,L2 baseline) -- flagged for review rather than treated as
   final if the distribution suggests the threshold doesn't discriminate
   (nothing passes, everything passes, or the baseline's own seed-to-seed
   IQR is comparable to the threshold).
3. Rank primarily by full-duration closed-loop VALIDATION behaviour.
4. Short/intermediate rollout metrics as supporting evidence -- this
   study's closed-loop protocol is full-duration-only, so this is reported
   as "not computed" rather than silently omitted.
5. Tie-break effectively-tied configurations on smaller and faster.

Output is a Pareto table (every metric kept separate) plus a hierarchical
sort column -- never a single collapsed score.

## Smoke tests

`scripts/run_smoke_test.py --dataset {cylinder200,bridge}` runs one tiny,
temporary end-to-end pass (H=32, L=1, seed=123, 1 epoch, one canonical
validation case for open-loop, one short 20s closed-loop trajectory for
the same case) and checks: test evaluation was never called; no test
metric/plot exists; the input is exactly `[h*, hdot*, Ur]`; the ND
transform was applied; the correct training-only scalers were loaded; a
checkpoint was produced; open-loop validation completed; closed-loop
validation reused the production Newmark path; the run's paths/receipt
are unique; and nothing under this study's own `results/` was touched.
All artifacts land under `smoke/`, invisible to `collect_results.py` by
construction (it only ever globs under `results/`).

## Tests

`tests/` covers all 12 required checks plus the corrections in this
revision (validation-only hard assertions, config-level/3-seed selection,
the frozen-manifest test-evaluation gate). Most are fast/synthetic;
`test_partitions.py` loads real cached CFD data and is the slow one in the
suite (run once, not in a loop) -- submit it via the same batch
conventions as everything else compute-heavy in this repo rather than
running it directly on the login node.

Run with:

    cd studies/gru_architecture_history_sensitivity/tests
    PYTHONPATH=../../../src:../scripts python3 -m pytest -q
